# Research: 功能收集与价值研究

## 1. 研究目标

本文件持续记录自动切片重做过程中的功能收集、用户价值研究、方法论调研和取舍结论。它不是任务清单，具体实施项放在 [TASKS.md](./TASKS.md)。

## 2. 当前结论

- 自动切片的核心价值不是“少点一次剪切按钮”，而是把下载后的音视频变成可理解、可检索、可复用的个人媒体资产。
- 本地切片必须成立，因为下载文件、用户隐私和即时浏览都在本机。
- 个人云端必须成立，因为长任务、远程浏览、跨设备素材库和 NAS/VPS 场景需要服务端持续运行。
- 原片上传必须可选，因为带宽、存储成本和隐私风险都很高。
- 结构化数据和向量数据是后续智能检索、推荐切片和素材库复用的基础。
- 商业价值不应只看“自动剪短视频”，而应看长内容复用、创作者产能、私有素材库、云端长任务和团队素材管理；详见 [BUSINESS-VALUE.md](./BUSINESS-VALUE.md)。

## 3. 第 1 轮：现有功能盘点

### 3.1 已有能力

- 下载完成后可触发后处理任务。
- 已有 AI 切片概念：`PostProcessTaskType.aiClipAnalysis`。
- 已有本地候选片段模型：`ClipSegment`。
- 已有切片记录模型：`ClipRecord`。
- 已有外部 Python sidecar 入口。
- 已有云端大模型配置档，但只是远程 JSON 分析端点。
- 已有 Clips 页面，可展示候选片段并做文本检索。

### 3.2 不可用根因

- 内置分析只是固定窗口候选，缺少真实内容理解。
- 切片结果没有上升为媒体资产库。
- 云端能力不是个人云端切片服务，没有上传、任务队列、对象存储和结果同步。
- 本地切片和云端切片没有统一任务模型。
- 结构化数据、向量数据、导出文件、日志和任务状态没有形成完整链路。

### 3.3 可复用点

- 下载完成后的后处理触发点。
- FFmpeg 执行器和进度处理经验。
- Settings 中已有 AI 云端配置 UI 思路。
- SQLite 持久化方式。
- Clips 页面作为未来媒体资产库入口。

### 3.4 需要迁移或废弃

- `AutoClipConfig` 只适合旧自动剪切，不足以表达 Edge + Cloud 策略。
- `ClipSegment` 需要迁移为 `ClipCandidate` 或兼容层。
- `ClipRecord` 需要迁移为 `ClipExportRecord`。
- 云端大模型 endpoint 需要并入 Cloud Profile 或 AI Provider，不等同个人云端 Server。

## 4. 第 2 轮：用户价值研究

### 4.1 内容创作者

价值：

- 快速从长视频中生成短视频素材。
- 保留标题、摘要、标签、转写和推荐理由。
- 云端可在电脑关闭后继续处理长任务。
- 可在 NAS/VPS 上集中管理素材。

风险：

- 自动切片质量如果不可解释，会降低信任。
- 原片上传成本高，需要明确上传控制。

### 4.2 个人知识库

价值：

- 下载的讲座、播客、课程可以变成可搜索片段。
- 向量检索可以按语义查找内容。
- 本地保留隐私，云端只在个人部署环境中工作。

风险：

- 只做短视频式切片会偏离知识管理需求。
- 需要同时支持视频和纯音频。

### 4.3 轻量团队或家庭服务器

价值：

- NAS 上统一保存和处理素材。
- 桌面端负责交互，服务器负责长任务。
- 可复用 Docker 部署。

风险：

- 多用户权限会复杂，MVP 不进入多租户。

## 5. 第 3 轮：功能地图

| 阶段 | 功能 |
| --- | --- |
| 下载后信息提取 | yt-dlp info、ffprobe、字幕、章节、缩略图、文件指纹 |
| 本地分析 | ASR、VAD、场景检测、关键帧、OCR、对象识别、embedding |
| 本地切片 | 候选片段、手动时间段、章节切片、FFmpeg 导出 |
| 本地浏览 | 媒体库、切片列表、时间线、搜索、预览、打开文件 |
| 上传云端 | 分析包上传、已切片上传、原片可选上传、断点续传 |
| 云端重切 | 云端队列、Worker、FFmpeg、AI 分析、日志 |
| 结果同步 | 任务状态、manifest、切片文件、冲突处理 |

## 6. 第 4 轮：架构可行性

### Docker 自托管

适合首版，因为 FFmpeg、队列、文件存储和 AI 依赖都需要长运行环境。

### Serverless

不适合作为首版主路径。Worker 类平台适合轻量 API 或状态同步，但不适合大文件、长时间 FFmpeg 和本地对象存储。

### 分块上传

必须支持。媒体文件通常较大，上传需要断点续传、hash 校验和取消能力。

### 对象存储

MVP 用本地目录映射，后续抽象 S3 兼容对象存储。

### 鉴权

MVP 用管理员密钥 + 设备配对 Token。多用户账号、OAuth 和组织权限不进入首版。

## 7. 第 5 轮：实施切片研究

### MVP

- 本地资产生成。
- 本地切片和浏览。
- 云端 Docker 服务。
- 分析包上传。
- 已切片文件上传。
- 云端任务状态和结果同步。

### Beta

- 原片分块上传。
- 云端 FFmpeg 重切。
- 云端 Web UI 预览。
- 向量检索。

### Pro

- 多设备同步策略。
- S3 兼容存储。
- 云端 AI 模型编排。
- 更完整的素材库管理。

- 云端 Worker 使用 SQLite 队列表还是轻量消息队列。
- 本地向量存储先用 SQLite JSONL 还是单独向量库。
- 原片上传确认交互的最小安全设计。
- 云端和本地模型版本如何写入 manifest。
